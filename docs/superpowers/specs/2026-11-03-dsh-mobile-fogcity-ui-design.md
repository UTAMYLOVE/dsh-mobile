# DSH Mobile 霧城原生介面（第二期）設計

日期：2026-11-03。對象：DSH Mobile（`app.dshmobile`），目標機 Galaxy S25 Ultra（arm64、Android 17）。
前一期規格：`docs/superpowers/specs/2026-11-02-dsh-mobile-design.md`（仍有效，本文件只描述介面改版）。

## 1. 為什麼要做

第一版（v0.1.0）在真機上能跑，但宇哥用了之後的感受：
- **畫面卡**：滑動、點按會頓。原因是整個介面是 dsh 自己的網頁，跑在 App 內嵌的 WebView 裡。
- **兩套設定很亂**：dsh 網頁裡有一份設定，App 的齒輪又有一份。
- **工作區選不了**（已在 v0.1.1／追加 1 修正，不屬本文件範圍）。
- 想要的外觀是他自己的「霧城」風格：粉色液態玻璃＋科幻儀表板（FUI/HUD），而且**炫和順都要**。

他怎麼用 dsh：**查資料、聊天、看 Claude 寫的小說**。不是拿來寫程式。

## 2. 目標、非目標、反目標

**目標**
1. dsh 原本的網頁畫面**整個不用**，換成 App 自己用 Android 原生（Jetpack Compose）畫的霧城介面；dsh 的功能保留（聊天、上網查資料、記憶、子代理人、Agent Teams）。
2. 五個分頁：總覽、對話、代理人、書架、設定；底部懸浮玻璃工具列（輸入框＋分頁）。
3. 對話頁：對話清單（分組、搜尋、新對話）、即時串流回覆、搜尋來源卡片、每個對話可切模型（Claude／DeepSeek）、長文一鍵「閱讀模式」。
4. 代理人頁：上方雷達總覽（誰派了誰、狀態）＋下方「監看牆」（每個代理人一塊小螢幕，即時顯示它正在做的事）；點開看完整過程、傳話、叫它停。
5. 書架＋閱讀模式：Claude 寫的小說收成一本本書，電子書式閱讀（字級、夜間、記得讀到哪、下一章）。
6. dsh 可以**主動提議新分頁**（用我們的零件拼），宇哥點頭才加；分頁內的數字更新不用每次問。
7. 又炫又順：玻璃、發光、轉動圓環、換頁動畫都要，同時不能卡。

**非目標**
- 不改 dsh 原始碼（紅線不變）。
- 不保留「開啟 dsh 原版畫面」的入口（宇哥決定：出問題找 Claude 修）。
- 不做霧城 2 的記帳／熱量功能（宇哥給的霧城資料只是參考）。
- 不做寫程式用的進階功能介面（檔案樹、diff 檢視、終端機）——dsh 仍可執行這些工具，介面只顯示通用的「工具執行卡」。
- 第一～四階段不做 dsh 的進階功能頁（插件、MCP、技能、排程任務、斜線指令、權限與代理人預設）。宇哥說**之後會用到**，列為第五階段（§5.10）；在那之前這些功能維持 App 啟動時的設定，不提供畫面。

**反目標（做了也算失敗）**
- 新介面比舊版還卡。
- 為了炫而讓文字難讀（水藍字放粉底、長文擠成一團）。
- dsh 能做、但新介面讓宇哥做不到的事（例如權限詢問看不到，dsh 就卡住）。
- 金鑰或 launch token 出現在任何記錄、錯誤訊息或畫面上。

## 3. 限制

- 紅線（沿用）：官方 dsh 一行不改；權限仍是 9 個；金鑰只在 Keystore，不進 env／設定檔／記錄；對話與使用統計上傳關閉；dsh 與閘道只綁 127.0.0.1。
- dsh 版本固定 0.2.1-rc.5；溝通協定沒有官方文件，以 `docs/dsh-ui-protocol.md`（本次實測報告）與 `docs/dsh-remote-map.txt`（144 個端點）為準。dsh 改版時要重新驗證。
- dsh 不提供任何金額；花費一律用 App 閘道既有的 `PriceTable`／`CostMeter` 計算。Lead 的 token 不含子代理人，總數要加總。
- 配色只用霧城六色＋兩個文字色：`#FEDFE1` 淡櫻粉（背景）、`#D7C4BB` 奶茶、`#DC9FB4` 粉紅（主色、發光）、`#FFFFFF` 白、`#A5DEE4` 水藍（第二重點，**只當填色／發光**）、`#9E7A7A` 玫瑰褐；主文字 `#5E4445`、次要文字 `#7D5F60`。
- 字體：英文標題 Orbitron、數字與英文小標籤 Chakra Petch（等寬數字）、中文系統字。Orbitron、Chakra Petch 為 OFL，打包進 APK。
- 風格基準：宇哥霧城 2 的原始碼 `docs/design-reference/fogcity2-app.css`、`fogcity2-motion.js`、`fogcity2-hud.js`，以及互動樣品 `docs/design-reference/dsh-redesign-mockup.html`（線上版 https://claude.ai/artifact/Qfo2GG1BKRdxMhwM8sd7Cj ）。新介面的圓角、玻璃、動畫節奏要對齊這些。

## 4. 考慮過的做法

| 做法 | 內容 | 取捨 |
|---|---|---|
| **一：原生 Compose 介面＋App 自己的 dsh 客戶端（採用）** | Kotlin 實作 dsh 協定（HTTP 單次呼叫＋`/api/remote.mux` WebSocket 串流＋`$events`），畫面全部 Compose | 最順、效果交給 GPU；監看牆／雷達／閱讀模式可做到很細。代價：工作量最大；Markdown、表格、程式碼要原生顯示；dsh 改版要跟著驗證協定 |
| 二：dsh client 插件取代整個網頁 | 用 `root` slot（priority −1）取代官方畫面，沿用 `ctx.remote` 與霧城 2 的 CSS | 較快、跟 dsh 貼最緊。但仍在 WebView，正是卡頓根源；玻璃模糊在 WebView 很吃效能 |
| 三：只換皮（CSS） | 保留 dsh 版面，換顏色字體 | 已在追加 1 做為過渡；做不出儀表板、監看牆、閱讀模式 |

宇哥選**做法一**（2026-11-03），理由：他最在意又炫又順，卡頓根源是網頁；實測協定很小（約 60 行就能跑完登入、開對話、串流、回答權限），原生化的風險可控。

## 5. 已決定的部分

### 5.1 架構
- **DshRemote（新）**：App 內的 dsh 客戶端。用現有的登入方式（launch URL token 換 cookie，`DshClient` 已有）；單次呼叫走 HTTP POST `/api/<ns>/<method>`；串流走一條 `/api/remote.mux` WebSocket（`open/item/end/cancel` ↔ `item/error/end`，以 `streamId` 區分）；斷線自動重連並重新訂閱；`$events` 的權限／提問事件以 `/api/$events/result` 回覆。所有連線只到 127.0.0.1、不經代理。
- **畫面**：MainActivity 不再載入 dsh 網頁；WebView 從主流程移除（下載處理等若仍需要另議，見 §6）。
- dsh 仍由現有 `DshController`／`DshService` 管理（啟動、崩潰政策、退版、心跳全部沿用）。

### 5.2 分頁
固定頁（dsh 不能動）：**對話**、**設定**、**總覽**（外框固定，內部小卡可由 dsh 提議增減）。
預設可變頁：**代理人**、**書架**（dsh 可提議調整或移除）。dsh 新增的分頁也屬可變頁。
分頁多到放不下時，工具列可左右滑。

### 5.3 總覽
今日 API 花費大圓環（對照通知門檻 US$5；DeepSeek／Claude 分開；本月）、代理人在跑數／上限、下次心跳、記憶提醒（心跳 dream 產生的 remind）、最近的對話（點了直接開）。

### 5.4 對話
- 對話清單：今天／昨天／更早分組、搜尋、＋新對話；每列顯示最後一句與模型。
- 訊息：串流逐字顯示；Markdown（粗體、清單、表格、程式碼）原生顯示；思考過程可折疊。
- 工具執行：通用「工具卡」（名稱＋參數摘要＋狀態）；**上網搜尋**特別顯示為「搜尋網路 · N 個來源」卡片與來源標籤，回答標註來源，點來源用系統瀏覽器開。
- 權限詢問與 ask_user_question：玻璃確認卡，必須能回答（反目標）。
- 每個對話右上角切換模型（DeepSeek Flash／Claude…，Claude 只有在有金鑰時出現）。
- 長回覆旁「📖 閱讀模式」。
- 第一階段就要有（避免「dsh 能做、介面做不到」）：附加圖片與檔案、中途停止回覆（`session/cancel`）、回覆進行中先送下一句（`session/prompt` 的 queue）、對話改名與刪除，以及一個**簡易代理人清單**（目前在跑的子代理人＋叫它停），直到第三階段監看牆取代它。

### 5.5 閱讀模式與書架
宇哥的寫法：**先給 AI 角色設定，再叫它寫**（2026-11-03）。
- **角色設定**：可重複使用的設定卡（角色、世界觀、文風等，宇哥自己寫或請 AI 幫忙整理），存在工作區。
- **開新書**：書架「＋新書」→ 填書名、選或新建一張角色設定、選寫作模型（預設「寫小說用的模型」，Claude 或 DeepSeek 都可以）→ 開一個專屬這本書的對話，角色設定作為這個對話的開頭設定。**一本書＝一個對話。**
- **章節**：這個對話裡模型寫出的正文回覆就是章節，自動收進書裡；宇哥可以把某則回覆標成「不是章節」或手動加入。一般聊天裡寫的故事不自動進書架，但可以用「加入書架」手動收。
- **閱讀模式**：電子書式全螢幕：字級、夜間、讀到幾 %、記得位置；「下一章」＝在這本書的對話請模型接著寫。
- **書架**：封面（霧城色漸層＋書名）、章數、閱讀進度。Claude 和 DeepSeek 寫的都算。
- 書、章節、角色設定都存在工作區（資料留在手機；匯出工作區時一起帶走）。

### 5.6 代理人（監看牆）
- 上方小雷達：總指揮在中心，子代理人依深度排內外圈，連線表示派遣關係；顏色表示狀態（水藍＝執行、粉紅＝等待、奶茶＝完成、深玫瑰褐＋閃爍＝出錯）；並行分段條；本次任務花費與 token 總計。
- 監看牆：每個代理人一塊小螢幕，即時顯示目前動作（🔍 搜尋、📄 讀取、✍️ 撰寫、🤖 派出、❓ 詢問、⚠️ 錯誤）與正在產生的文字；時間、花費、token 條。
- 點開：完整步驟、傳話給它（`subagents/prompt`）、叫它停（`subagents/interruptByParent`）。
- Agent Teams：顯示隊友（`agentTeam` 的 members/phase）與任務板（tasks）。
- 資料來源見 `docs/dsh-ui-protocol.md` §4（`session/control` 投影、`$events` 的 `api-session/added|status|removed`、子代理人 `session/follow`）。

### 5.7 dsh 提議新分頁
- App 提供一組霧城零件：大圓環、小圓環、長條圖、進度條、格子、清單、數字讀數、雷達、文字卡。
- 新增一個 dsh 插件工具（例如 `dshm_page_propose` / `dshm_page_update`）：dsh 用宣告式資料（JSON：零件種類＋資料）提議或更新分頁，**不能放任何程式碼**。
- 提議（新增、刪除、換版型）→ App 顯示玻璃提案卡（縮小預覽＋說明），按鈕：加上去／不要／改一下；宇哥拒絕過的提案要記住不再重提。
- 已核准分頁的**資料更新**直接生效，不再詢問。
- 資料來源（Claude 的決定）：零件可以綁定 App 已有的即時數值（今日花費、在跑代理人、下次心跳等，App 自己更新），其餘數值由 dsh 在對話中呼叫更新工具時寫入；**預設不在背景花錢更新**。若某分頁需要定期自動更新（例如天氣），提案卡上要寫明頻率與估計費用，宇哥同意才由心跳執行。
- 固定頁（§5.2）不受此工具影響。

### 5.8 設定
App 現有設定全部搬進新介面（金鑰、代理人數量／深度／團隊、模型、預算與硬上限、心跳間隔、dsh 版本更新與退版（**只能更新到 App 已驗證過協定的 dsh 版本**：清單隨 App 一起發佈；新 dsh 版本要先驗證協定再跟 App 更新推出——Claude 的決定，因為沒有原版畫面可退，新版若悄悄破壞協定會讓介面全失效）、子行程限制狀態、匯出錯誤記錄／記憶／工作區），新增「效果強度」（全開／平衡／省電，預設全開）與「寫小說用的模型」。dsh 網頁裡的重複設定不再出現（網頁不用了）。

### 5.9 又炫又順的做法
- 玻璃模糊、發光用 GPU（Android 12+ `RenderEffect`），只在可見區域。
- 只有當前頁的動畫在跑；切走、背景、關螢幕全部暫停。
- 靜止時背景（光暈、網格）放慢；閱讀模式背景效果降到最低。
- 偵測掉格：連續卡頓時自動先關模糊，再關背景動畫；「效果強度」可手動調。
- 系統「減少動態效果」開啟時關閉非必要動畫。
- 目標：一般操作 120Hz 下不掉格（S25 Ultra）；以 Macrobenchmark／JankStats 在 CI 模擬器量測並設門檻。

### 5.10 發佈節奏
分階段，每階段發一版：
1. 原生殼＋對話（含清單、串流、搜尋來源、權限卡、模型切換）＋設定＋總覽基本版；
2. 書架＋閱讀模式；
3. 代理人監看牆；
4. dsh 提議分頁；
5. dsh 進階功能頁（插件、MCP、技能、排程任務、斜線指令、權限與代理人預設）。

## 6. 留給實作者決定的事

- Compose 的 Markdown 顯示用哪個函式庫（需 Apache/MIT 類授權、可離線、支援表格與程式碼）。
- DshRemote 的內部結構（Flow／協程設計、重連策略細節），只要對外行為符合 §5.1。
- 小說「一本書」的資料格式與在工作區的路徑；怎麼判斷一則回覆屬於哪本書／第幾章（可用對話標題與模型提示）。
- 下載檔案（dsh 產生的檔案）在沒有 WebView 後如何交給系統分享：沿用 `Exporter`。
- 各階段的測試切分；e2e 改為驅動原生畫面（Compose UI test）＋假模型。
- 效能門檻的實際數字（以第一階段量測結果訂定）。

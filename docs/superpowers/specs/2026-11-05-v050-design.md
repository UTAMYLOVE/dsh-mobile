# DSH Mobile 0.5.0 — design

Owner: 宇哥 (non-technical, Traditional Chinese). Approved mockups: https://claude.ai/artifact/2tT9tm2YSXdkeeo3cbL1PB
(nine phone screens: 1 對話長按選單＋建議下一步, 2 輸入框的＋, 3 計畫模式・進度條・沉思, 4 深度研究・成品・畫圖,
5 對話清單, 6 專案／小助理, 7 常駐小幫手, 8 長對話目錄, 9 鎖定・分享進來).

## Intent

The owner compared ChatGPT, ChatGPT Work, Claude, Claude Code, Gemini, Grok (Bot), Meta Muse, Perplexity and DeepSeek and
wants everything worth having in DSH Mobile, "盡量做完整", in ONE release (0.5.0) that also fixes what is broken now. He
uses the app for Taiwan-stock research, writing a novel, bookkeeping and looking things up, on his phone, with a large
system font. He wants it run end to end and to be handed the file; he does not want progress chatter.

## Goals

0.5.0 ships, tested on the emulator in CI:

## Non-goals

- Photo-real image or video generation (DeepSeek has none).
- Gmail / calendar connectors (needs new permissions and handing over accounts).
- Restoring files changed by the agent (branching restores the conversation only).

## Anti-goals (a failure even if it works)

- Any color outside the app palette: `#FEDFE1` background, `#DC9FB4` primary, `#A5DEE4` aqua, `#D7C4BB` milk tea,
  `#9E7A7A` rose brown, `#5E4445` text, `#7D5F60` secondary, `#A98F90` faint, white, and their alpha tints. No blue, green
  or red badges (the owner, 2026-11-05: 「顏色還是只能我們選的那幾個」).
- A cluttered dock: still five tabs; new things live in the existing screens (approach A).
- Layouts that break at a large system font scale or with long Chinese titles.
- Anything that slows ordinary chatting: modes are opt-in per message, the app skills stay out of the novel/bookkeeping flow.

## Constraints

- Official dsh unmodified; only its RPCs, patch rows, skills and the native shim.
- Exactly the nine permissions already declared; voice, camera and lock go through system activities.
- Keys only in the Android Keystore; dsh gets the fake key; no `.env`; telemetry and transcript upload off.
- Both runtimes (proot and native) work; all paths come from `DshLayout`.
- Public releases repo holds only APKs; only the owner tags; push only to `claude/dsh-mobile-cloud-handoff-vfhvdh`.
- No subagents for the build (cost); one inline implementer.
- Fonts: Chinese system font, Chakra Petch for numbers/English, Orbitron only for large English titles.

## Approaches (decided)

- A (chosen by the owner): everything inside the existing screens — long-press menus, the ＋ sheet, the conversation list
  with tabs, sub-pages for a project and the helpers.
- B (rejected): a sixth 「工作」 tab for the big-work features; crowds the dock and splits work from conversation.

## Decided with the owner

- One release, 0.5.0, fixes plus all features. Approach A. Colors from the palette only. Features as complete as possible.
  The nine mockups are the reference for layout and wording.

## Calls made by the builder (owner may correct)

- Edit/re-answer branch into a new conversation (dsh's model) instead of in-place versions; the menu says so.
- Projects and custom assistants are one thing (a project shown as an assistant).
- Helpers are dsh schedules inside one conversation per helper, so the agent itself can create them from chat.
- Temporary chats are archived (dsh's delete), and memory writes are asked against by instruction (dsh offers no switch).
- Follow-up suggestions come from the model (a marker block), not from a second model call, to cost nothing extra.

## Left to the builder

- Exact component structure, tags, strings; the order of work; how each feature is unit- and e2e-tested (every feature
  gets at least a unit test; FakeModel scenarios for plan, todos, present, schedules and follow-ups in e2e).

## Added by the owner after approval (2026-11-05), to design and build in 0.5.0

Not yet designed in detail; each needs a short brainstorm/mockup before building.

1. **Chat header too tall (~40% of the screen).** Remove the stats block above the messages (effort/review line, context bar,
   two stats lines; 加入書架 and 數據 go into a header ⋮). The title row stays one line.
2. **Status line in the chat box, ccstatusline-style** (the owner: 「做成 claude code 的模組那種」). Powerline segments above the
   input row inside the dock: model ▶ 思考 ▶ 審查 ▶ 上下文 (mini bar, %) ▶ tok/s ▶ conversation cost; updates when a reply ends;
   tapping 思考/審查 changes them, tapping 上下文 opens the data panel; Settings chooses which segments show and their order.
   Palette colors only. References: ccstatusline (sirmalloc), cc-statusline, claude-code-statusline.
3. **Claude leads, DeepSeek works.** Claude as the lead model (default `claude-opus-5-5`, $4/$20 per MTok; a switch to
   `claude-fable-5-1`, $10/$50, for the hardest work); subagents run on DeepSeek. dsh 0.2.1 gives subagents the lead's
   model, so the app's gateway reroutes subagent requests to DeepSeek's Anthropic-compatible endpoint (identify subagent
   requests by session; verify how before building). Needs the owner's Claude API key in the vault.
4. **Weather: our own precise analysis** (「要自己分析全新」). Multi-model forecasts (ECMWF, GFS, ICON, JMA, CMA, KMA via
   Open-Meteo, plus CWA), agreement → confidence; bias correction from the nearest CWA station's recent observations
   (weights per model, systematic offsets); nowcast for the next 2 h from radar; ensemble (≈50 members) rain probability and
   amounts; every answer states confidence and why. CWA open-data key in the vault, fetched by the app's gateway (never
   handed to dsh). A weather card in the app's style; daily brief and helpers use it.
   **Open question for the owner:** location — he asked for it; it would be a 10th permission (coarse location, while in
   use only, never background, never given to dsh). Ask him to confirm changing the nine-permission rule before adding it;
   manual place entry works either way.
5. **War room redesign** (「太簡陋、頁面太長、資訊分太開、太重複」). Today ~15 sections repeat the same numbers (speed ×3,
   running/done/error ×3, tokens per agent ×2, cost ×2, logs ×3). Target four: a top summary strip (the only place numbers
   appear), an agent board (one rich row per agent: name, stage, speed sparkline, tokens, cost, stop; tap for details), one
   hero chart (orb + speed merged, switch speed/tokens/cost), one timeline (decisions + tools + log, filter chips
   全部/放行/擋下/等你/錯誤). About 1.5 screens. Mockup first (the owner picks).
